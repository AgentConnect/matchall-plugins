## 已批准的保留目标

下面的 30/90 天、12 个月是结合产品需要提出的期限，并非英国法律统一规定。
需为每类数据记录用途、负责人、清理触发时间及例外；公开承诺必须与实际处理能力一致。
[ICO 存储期限原则](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-protection-principles/a-guide-to-the-data-protection-principles/storage-limitation/)
要求期限与必要用途相符，且要定期复查。

| 数据类别 | 建议期限与起算点 | 理由及实际处理 |
| --- | --- | --- |
| 账号、正在使用的意向、用户主动保存的暂停意向 | 提供服务期间按需保留；连续 12 个月无用户实际操作时复核，拟清理前预留 30 天通知/保留窗口 | 支持持续匹配和稍后恢复。暂停本身不触发删除；后台轮询不重置用户活跃时间。无绑定邮箱时的告知方式须先设计，不能假称已通知 |
| 从未激活的草稿 | 最后编辑后 90 天 | 留出继续编辑时间；之后删除业务文本及派生数据。实施前在产品告知 |
| 已关闭、已完成或已过期的意向 | 结束后 90 天 | 供用户查看近期结果；到期清理原始文本、结构化字段、向量、缓存及不再需要的联系数据。提前删除请求单独处理 |
| 私密联系方式及版本 | 关联有效意向/授权需要期间；失效版本不再展示，必要性复核后最迟随相关意向清理 | 不把历史原文长期保存在日志、审计或通知中；同意/撤销的最少证据另列 |
| 一般运行日志 | 产生后 30 天 | 排查近期故障；不记录密码、令牌、联系方式原文或完整匹配文本 |
| 必要安全和同意审计 | 事件发生后最多 90 天；确有必要保全的事件单独审批与复查 | 核对异常访问及授权。只是默认上限，不是无限期“安全例外” |
| 支持请求、删除处理凭证 | 工单完成后最多 12 个月，删除不必要附件和原文，仅保留处理所需内容 | 便于追踪投诉和证明处理结果；届满复核并清理，仍需必要性说明 |
| 常规备份 | 备份生成后滚动 30 天到期 | 仅灾难恢复使用，覆盖数据库、配置和临时副本；旧的手工快照也要纳入清单。恢复时先重放删除记录再开放服务 |
| 模型、邮件、托管服务商的数据 | 按真实服务商条款与设置逐项列明；暂不填虚构期限 | 核实处理地区、日志、训练用途、子处理商和删除能力；不能笼统承诺所有供应商同步清空 |

## 删除请求：响应期限与备份分别说明

建议内部目标为 28 天，通常法定答复期限为一个日历月，及时处理而非等到最后一天。
记录收件日；仅在适用规则允许时处理身份核验与延期，并通知原因及正确截止日。
支持邮箱是方便的入口，不把其他有效渠道收到的请求直接作废。
[ICO 删除权指引](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/individual-rights/right-to-erasure/)
还区分了在线数据与备份：待轮换的数据应处于不可使用状态，并向请求人说明。

**不使用“核验后 30 天删除一切”的旧表述。** 需要依法保留的具体记录逐项解释，
不得以笼统安全理由保留整套账号资料。联系撤销不能收回对方已经复制的信息。

## 与真实功能对应的验收用例

- 买方删除后，旧 access/refresh token 及浏览器会话不能重新取得该账号数据；其他卖方账号仍正常使用。
- 一条意向的多个版本、联系方式历史、匹配向量、公开摘要、缓存与待发通知都被覆盖；删除中的后台任务不能把数据重新写回。
- 已有双方同意时，一方删除后 API 不再泄露其联系原文；对方独立持有的记录按已确认规则处理，不删除整张关联表。
- 重试同一删除任务不会破坏其他数据；中途失败不会报告“全部完成”，补偿步骤可追踪。
- 从删除前的备份恢复到隔离环境，先应用删除标记，再允许业务查询；不能重新激活已删除账户。
- 备份边界包含 29/30/31 天以及手工副本；只读预览与实际候选集合相同，不触及保留范围外的数据。
- 日期计算覆盖月末、二月、闰年、周末/适用假日、必要核验和合法延期；不能简单统一加 30 天。
- 暂停意向可以正常恢复；后台匹配/自动轮询不让无人使用的账号永久逃过闲置复核。

未执行迁移、清理或备份删除。下列现有对象足以说明为什么不能直接按时间批量删表。

| 数据及现有位置 | 实施要求 |
| --- | --- |
| `intents`、`intent_versions`（迁移 0001、0002、0007） | 0001 的 `intent_versions_immutable` 在 UPDATE 或 DELETE 前拒绝操作；0004 临时关闭后又重新启用。普通级联删除会受此触发器阻挡。设计限权、审计的删除通道；不能全局停用完整性保护后任意删表 |
| `intent_extraction_runs`、`intent_field_candidates`、`intent_representations`、`intent_attr_*`、`intent_generic_profiles`（0004、0007、0020） | 覆盖原始输入、字段、检索词和向量的所有历史版本；清理作业之外还要防止排队抽取/向量任务重新写回 |

### 需要新增或明确的事件时间

- 当前 `intents` 有通用 `updated_at`，但本轮未发现独立 `closed_at`、`fulfilled_at`
  或账号 `last_user_activity_at` 字段。后台过期处理也会改动 `updated_at`。
- 90 天已结束意向保留要锚定实际结束事件；从未激活草稿要锚定最后用户编辑。
  不能把“最后任何更新”统一当成这两个时间。
- 12 个月闲置复核需要真实用户活动和通知状态。登录、服务端轮询、定时匹配和
  用户明确操作应分别定义；未知历史活动时间不能自动按最早日期认定已过期。
- 历史时间只在有可靠事件证据时回填；没有证据的记录进入人工复核，不能伪造时间。

### 推荐开发与验收顺序

1. **清单和只读预览**：盘点实际已部署表、第三方及备份副本；按批准目标计算候选，
   输出类别、数量、触发原因、无法判断的记录和双方影响，不输出联系方式原文。
2. **受理和冻结**：创建数据请求编号、收件日和负责人；在必要范围确认账号控制权。
   先设计可恢复的业务停写/停通知状态与授权撤销，保留支持和数据请求入口。
3. **限权删除流程**：设计删除状态机、跨库顺序、版本表触发器兼容、幂等重试与失败
   标记；每项完成后校验，失败不得显示“全部删除”。保留最小恢复抑制记录及必要例外。
4. **日志与备份**：实现 30 天目标和超期告警；清理前先核对恢复能力、保留范围与
   手工副本。已有生产数据的实际销毁另行确认具体候选范围。
5. **合成数据验收**：除上面的业务用例外，覆盖跨意向引用、immutable trigger、
   非所有者参与记录、旧幂等回执、后台任务竞争、失败重试和跨库授权失效。
6. **正式披露**：核实实际服务商、处理地区、法律依据及转移安排，将已验证能力写入
   正式页面，保留人工流程的真实说明；再生成下一版含正式链接的插件包。

1. 在网站注册/授权、插件介绍及正式条款中清楚说明 18+，并使各入口一致。
2. 评估实际儿童访问风险，选择与风险相称的年龄保障措施；不能仅把勾选框当成

   也不能因第三方登录成功就推定成年。资格不足或未完成必要检查时拦截需成年人
   资格的新业务操作，并给出清楚的处理入口。
4. 对已知未满 18 岁用户，停止新意向发布、匹配参与、联系交换及活动报名等
   成人服务操作。数据请求和支持渠道仍应可用。既有账户如何处理须有单独流程，
   不因本次年龄决定直接批量删除用户或数据。
5. 使用合成年龄/资格结果验收：17 岁不能进入上述操作，18 岁边界按规则通过；
   未知资格不能被静默当成成年；绕过网页直接调用 API/MCP 仍受服务端限制。
   确认系统不根据姓名、头像或职业猜测年龄，且日志不保存额外身份材料。
