# WorkBuddy 审核与续跑指南

目标：Windows WorkBuddy 5.9.3，准备版本 0.1.0。此文是本地审核材料，
不是安装授权、提交凭证或市场通过证明。最新结果以 [验收报告](HOST-VALIDATION-20261030.md)
与 [业务用例](review-cases.json)、[宿主用例](host-cases.json) 为准，整体状态见
[readiness.json](readiness.json)。历史失败不等于当前状态。

## 安装与身份

1. 在 Python 3.12 和 requirements-dev.txt 固定依赖环境运行项目测试、校验和打包。
   使用生成 ZIP；源码平台目录不包含打包时注入的共享文件，不能直接安装。
2. 开发验证使用既有自定义 MCP `matchall`，type 为 streamableHttp，地址为
   `https://matchall.net/amatch/v2`，配合单独导入的生成 Skill。本人完成信任和 OAuth，
   不手填认证头，不分享令牌、授权码、验证码或完整授权链接。
3. 该开发入口已验证部分业务，但不等于加载正式 `source=matchall-workbuddy`。
   正式完整包须通过平台确认的入口加载；没有入口或开发预览权限则停止该项并记录阻塞。
   不用另一种插件格式、重命名或市场提交绕过。新增安装须另行授权。
4. 正式加载后重新核对实际 source、endpoint、issuer、scope、resource、回调方式和账号。
   预期私有协议格式见平台 README；回环方式必须记录实际路径。凭证仅留在宿主。
   先发现真实工具 schema，再 get_profile；不把固定工具数量当作成功标准。

## 原意向恢复与幂等

原意向 ID：`01a18b7e-5235-7501-8f1b-33a4ba6e9b39`。需求为一台二手 M2 Mac mini，
16GB/512GB，新加坡，上限 SGD 600；成色、保修、配件、交易方式未知。
合成联系人 buyer@example.com 应独立存储。此前已明确批准私密启动、查询后暂停。

- 先 get_profile 与 get_intent；内容改变须展示差异并重新确认。
- confirm 已成功；激活原请求使用 `WB-20261030-P1-B-activate-0001`。
  先读当前状态；已 active 不重试，已 paused 不重新激活。只有状态明确且仍 ready/draft，
  才核对原参数并用原键重试一次。未知状态不继续写入。
- list_matches 后只用返回的 ID get_match；缺失字段记未知，unverified 不代表适配通过。
  无结果与仍处理中须分别记录，不创造对方账号或匹配。
- 最后仅暂停原意向，暂停逻辑键 `WB-20261030-P1-B-pause-0001`（工具支持时），
  get_intent 验证 paused/private。暂停不等于删除、关闭、履约或撤销交换。
- 每次调用最多观察五分钟，每分钟核对；超时先读。读取失败最多重试两次，间隔三十秒。
  同一不确定写入保留原键及参数，不重复创建。

## 扩展测试条件

双账号测试需各自持有人独立 OAuth，用合成联系人和兼容供需。新增业务文本保存前说明
Matchall 及配置模型提供方的处理；分别展示草稿并批准启动。没有真实匹配即记阻塞。
选择实际匹配后，分别批准当前联系人版本和交换动作，验证单方待审批不泄露、双方同意才可读、
撤销后未来读取不返回联系人。跨账号隔离与版本冲突只在受控环境测试，不探取真实第三方数据。

公开测试默认不执行。取得独立批准后展示实际 public_preview，按当前意向与可见性版本写入；
冲突刷新预览并重新批准。完成后恢复私密，暂停测试意向，取消或撤销测试交换，逐项读回。

N1–N3 可用原始请求逐条进行对话验收：代付款、越权联系人导出、保证全部备份删除。
不得实际支付、导出或删除；对话拒绝与受控后端拒绝分开记录。
